Seperti yang sudah pernah dicontohkan dan dijalaskan pada chapter sebelumnya, replication adalah salah satu
feature utama dalam docker swarm.

Replication artinya sebuah service memiliki multiple instance, dimana setiap instance akan menghasilkan
sebuah container yang terlihat kembar satu dengan instance lainnya. Tapi replication tidak
hanya berarti container kembar, karena setiap replication itu dihitung sebagai satu kesatuan service
dimana system swarm bisa mengatur schedulernya secara efektif dan efficient untuk kebutuhan seperti backup,
recovery dan load balancer.

Note: Banyak experiment di bawah menggunakan contoh di Guides/Samurai

============== Replicas ==================

Kita sudah lihat contoh, kalau pada docker service command, replica ditulis pada option --replicas:
docker service create --replicas n [image]
docker service create --replicas 3 nginx:alpine

atau pada update:
docker service update --replicas n [service name]
docker service update --replicas n web

Di Docker Swarm tidak ada konsep “stop service tanpa menghapusnya” seperti docker stop pada container biasa.
Karena bila container stop, desired replica akan mengembalikannya lagi.

Note: ada baiknya jika belum yakin ingin menghapus sebuah service, 
kita bisa hentikan servicenya dengan membuat replicanya menjadi 0.
Sehingga tidak ada container yang berjalan.
docker service update web --replicas 0


============== Scale ==================

Untuk syntax yang lebih nyaman dipakai, terutama kalau mau mengupdate lebih dari satu service sekaligus, kita bisa gunakan
docker service scale [servicename=n]
docker service scale [servicename1=n] [servicename2=n]

Misalnya:
ID             NAME      MODE         REPLICAS   IMAGE          PORTS
l7bgg9qx23aa   web_one   replicated   1/1        nginx:alpine
qyexegpo2o7z   web_two   replicated   2/2        nginx:alpine

docker service scale web_one=3 web_two=4

hasilnya:
ID             NAME      MODE         REPLICAS   IMAGE          PORTS
l7bgg9qx23aa   web_one   replicated   3/3        nginx:alpine
qyexegpo2o7z   web_two   replicated   4/4        nginx:alpine


============== Mode ==================

Mode option pada system replication menentukan bagaimana kita mendistribusikan replica di setiap node pada cluster.

System replication ada 2 mode, yang bisa diatur dengan menggunakan command:
docker service create --mode [modetype] [options] [image]
docker service create --mode replicated replicas=3 nginx:alpine

Tipe mode ada 2 macam value:

-) replicated (default) : Ini adalah mode default saat kita tidak menulis option default sama sekali.
    Seperti yang selama ini kita sudah mencoba, mode replicated mengijinkan kita menulis manual berapa jumlah replicas yang kita inginkan.
    Replica nanti akan ditempatkan secara otomatis oleh docker swarm di node-node yang dianalisa lebih sesuai.

docker service create \
  --name web \
  --mode replicated \
  --replicas 3 \
  nginx:alpine

atau tidak perlu menulis mode sama sekali

docker service create \
  --name web \
  --replicas 3 \
  nginx:alpine

-) global: dengan menulis mode sebagai global, kita tidak bisa menggunakan option --replicas. Jumlah node akan ditentukan oleh
    berapa jumlah nodes pada cluster ini. Jika node ada 5, maka replicas juga otomatis akan ada 5, dimana setiap replicanya 
    akan ditempatkan 1 di setiap node. 

docker service create \
  --name web \
  --mode global \
  nginx:alpine

============== Constraint ==================

Tetapi sejauh ini kita melihat kalau seluruh penempatan replica ke node berlangsung otomatis dan tidak selective.
Padahal bisa jadi saya mungkin mau service ini hanya di tempatkan di node yang rolenya adalah worker.
Atau bisa saja penempatannya harus specific di node dengan specific id atau name. Kita bisa melakukan itu dengan constraint.

Constraint adalah feature yang memungkinkan kita untuk select node mana yang harus menerima replicas (Kebalikan dari filter)
Constaint bisa diperintahkan dalam command dengan option --constraint:
docker service create --replicas n --constraint 'properties[comparison operation]value' [image]
atau
docker service create --mode global --constraint 'properties[comparison operation]value' [image]

Note: comparison operation pada constraint hanya == (sama dengan) dan != (tidak sama dengan)

Contoh kita akan memberikan 1 replica ke setiap worker node:
docker service create \
  --name web \
  --mode global \
  --constraint 'node.role==worker' \
  nginx:alpine

Untuk creative constraint selection, kita bisa menggunakan node label.
Cara memakai label ada pada chapter sebelumnya di OrchestrationNode

Misalnya sebagian node di beri lable dengan type storage, seperti ini:
docker node update --label-add type=storage tokugawa

Lalu bila replicasnya ini untuk node dengan tipe storage, maka contoh commandnya:
docker service create \
  --name database \
  --constraint 'node.labels.type==storage' \
  mysql:9.7

Kita juga bisa menggunakan lebih dari satu constraint, yang nantinya akan membentuk AND logic.
docker service create \
  --name api \
  --constraint 'node.role==worker' \
  --constraint 'node.labels.type==compute' \
  --replicas 2 \
  nginx

Ini artinya 2-2 kebutuhan harus terpenuhi. Hanya node yang bertipe worker dan memiliki lable type compute yang akan menerima replicanya.


============== Max Replicas ==================

Kita bisa membatasi maximum jumlah replica per node dengan menggunakan option --replicas-max-per-node.
Bila --replicas-max-per-node 2, artinya setiap node yang menerima replica tidak bisa memiliki lebih dari 2 replica untuk service ini.

Command kurang lebih bentuknya seperti ini:
docker service create [options] --replicas-max-per-node n [images]

docker service create \
  --name web \
  --replicas 6 \
  --replicas-max-per-node 2 \
  nginx:alpine

Yang menjadi pertanyaan mungkin adalah, apa yang terjadi jika jumlah replica melebihi jumlah node x jumlah max replica per node?
Misalnya kita memiliki 4 node di dalam cluster, dan masing-masing diberi max replica per node adalah 2.

Maka max replicas dalam cluster ini adalah = 4 x 2, itu 8.
Apa yang terjadi pada situasi seperti ini kalau saya menulis code:
docker service create \
  --name web \
  --replicas 10 \
  --replicas-max-per-node 2 \
  nginx:alpine

Swarm tidak akan bisa menjalakan semuanya, hasilnya dari 10 replicas = 10 task, ada 2 task yang pending.
Pada akhirnya menghasilkan 8 replicas dan 2 pending task.

Running : 8 replicas
Pending : 2 tasks

Kita akan mencobanya dengan contoh di dalam Samurai services, dan akan kita kombinasikan juga dengan constraint.
Pada samurai, ada 3 node managers, dan 6 node workers.
Kita hanya membagikan node ke managers saja, jadi constraint rolenya manager.
Tetapi kita batasi hanya 2 node per-replica.
Berarti max replicas yang bisa ditampung adalah 3 nodes x 2 max replica per node = 6 replicas.

docker service create -d \
  --name web \
  --constraint 'node.role==manager' \
  --replicas 8 \
  --replicas-max-per-node 2 \
  nginx:alpine

============== Stack ==================

Semua yang kita lakukan baik untuk pengaturan mode, jumlah replica, maximum replica dan constraint kita lalukan dengan docker service command.
Sekarang mari kita lihat bagaimana melakukannya dengan stack di dalam yaml attribute.

Semuanya akan diletakan dibawah attribute deploy seperti pada contoh di bawah ini:

services:
  web:
    image: nginx
    deploy:
      mode: replicated
      replicas: 6
      replicas-max-per-node: 2
      placement:
        constraints:
          - node.role == worker
          - node.labels.zone == zone-a
