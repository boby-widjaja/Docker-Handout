Pada saat kita melakukan deployment app kita ke sebuah server, baik itu berada di dalam virtualization maupun
di dalam container, kita pasti tidak terlepas dengan sensitive data. Sensitive data yang saya maksud di sini
adalah informasi seperti:
-) password database
-) API key
-) private key
-) token
-) certificate
-) credential aplikasi
dan lain sebagainya.

Contohnya pada saat kita belajar Dockerfile, kita diminta untuk menginput value dari ENV (Environment Variable)
berupa password database dari app.

Seluruh sensitive data di atas harusnya bersifat rahasia, dan tidak boleh sampai sebagian admin pada server
sekalipun bisa melihatnya. Apa lagi kalau server mendapatkan serangan dari luar lalu sensitive data tersebut dapat diintip.
Lokasi yang tidak baik untuk menaruh sensitive data/ credential tersebut kalau berada di konfigurasi, image, repository, 
atau environment container. Dimana semua hal-hal ini dapat di inspect.

Untuk itu docker swarm menciptakan feature yang namanya Secret.
Docker Secret adalah mekanisme Docker Swarm untuk menyimpan data sensitif dalam bentuk ter-enkripsi, sehingga
tidak bisa dilihat oleh umum dengan sembarangan.

Note!: Secret adalah feature dari docker swarm dan hanya berlaku di docker swarm.
Jadi secret yang kita belajar di sini tidak akan aktif featurenya bila kita tidak meng-inisiasi swarm.

Pertama-tama kita harus membuat secret dahulu dengan command ini:
docker secret create [secret name] [stdin]
docker secret create postgres_password ./postgres_password.txt

atau terima dari pipe terminal input

echo "postgres" | docker secret create postgres_user -
(Note: - ada untuk terima terminal input)

Gunakan command ini untuk lihat semua secret yang ada:
docker secret ls

Kita bisa inspect secret, tapi tentu saja isinya di encrypt:
docker secret inspect postgres_password

Hanya ini hasilnya:
[
    {
        "ID": "o6q9onz2eqrf1z7otpqbat5o7",
        "Version": {
            "Index": 23
        },
        "CreatedAt": "2026-09-05T15:25:06.111411505Z",
        "UpdatedAt": "2026-09-05T15:25:06.111411505Z",
        "Spec": {
            "Name": "postgres_password",
            "Labels": {}
        }
    }
]

Secret memang di-encrypt dari mata kita, tapi seharusnya bisa dibaca oleh container di dalam service.
Misalnya harus bisa dibaca oleh databasenya pada saat proses pembuatan service.
Karena itu kita harus sambungkan secret dengan service atau container:

docker service create \
  --name my_postgres \
  --replicas 1 \
  -p 5432:5432 \
  -e POSTGRES_USER_FILE=/run/secrets/postgres_user \
  -e POSTGRES_DB=mystore \
  -e POSTGRES_PASSWORD_FILE=/run/secrets/postgres_password \
  --mount type=volume,source=postgres_volume,target=/var/lib/postgresql/data \
  --secret postgres_user \
  --secret postgres_password \
  postgres:17.10

Note: Detail contoh exercise ini bisa ditemukan di Guides/SwarmSecret/PostgreSQL
Untuk tujuan percobaan ini, tolong gunakan 1 replica terlebih dahulu. 
Karena sistem persistent storage (volume) untuk multi replicas sedikit berbeda, dan saat ini kita fokus untuk secret dulu.

Check nama container yang baru saja dibuat dengan docker ps atau docker container ls,
lalu catat namanya atau idnya, misalnya:
my_postgres.1.v72eohflw4bai82b1ce2jpv83

Masuk ke dalam container dengan bash:
docker exec -it my_postgres.1.v72eohflw4bai82b1ce2jpv83 bash

Kita bisa menemukan telah dibuatkannya directory /run/secrets, lalu di dalamnya ada file secretnya dengan nama postgres_password dan postgres_user.
Kedua file secret ini sudah tidak lagi menjadi secret dan sudah tidak lagi encrypted, sehingga bisa dibaca oleh container.
Sekarang kalian bisa langsung baca, silahkan test dengan concat command:
cat /run/secrets/postgres_password

Keuntungan secret dibanding lewat environment variable atau lewat configuration adalah
dengan memperkecil kemungkinan sensitif information dibaca sepanjang lifecyle pembuatan service atau container.
Tetapi pada akhirnya docker container juga harus dijaga lewat linux untuk tidak sebarangan bisa di execute.

Kalau mau menghapus secret caranya juga sangat stereo tipikal.
docker secret rm postgres_user


============== STACK =================

Kita sudah mencobanya dengan docker service command, sekarang kita coba dengan menggunakan stack yaml file.

Kurang lebih seperti ini yaml filenya:

services:
  my_postgres:
    image: postgres:17.10
    environment:
      POSTGRES_USER_FILE: /run/secrets/postgres_user
      POSTGRES_PASSWORD_FILE: /run/secrets/postgres_password
      POSTGRES_DB: mystore
    ports:
      - "5432:5432"
    volumes:
      - postgres_volume:/var/lib/postgresql/data
    secrets:
      - postgres_user
      - postgres_password
    deploy:
      replicas: 1
volumes:
  postgres_volume:
    external: true
secrets:
  postgres_user:
    external: true
  postgres_password:
    external: true

Note: Detail contoh exercise ini bisa ditemukan di Guides/SwarmSecret/PostgreSQL pada bagian external secret.
Secrets memiliki attributes sendiri, di register terlebih dahulu, baru bisa dipakai di setiap servicenya.
Lalu seperti biasa kalau environment variablenya harus menunjuk ke directory internal tempat secret sudah di decrypted.

Contoh tersebut masih menggunakan secret yang sudah jadi terlebih dahulu, itu sebabnya ada attribute secret pada bagian secret.
Sama seperti volume yang kalau kita menggunakan yang sudah ada, kita beri attribute external.

Kalau mau menggunakan yaml untuk stack yang membuatkan secret sekaligus, kita bisa coba experimentnya di directory yang sama,
tetapi pada bagian All in One. 

Bagian secretnya 2-2nya diambil dari file text:

secrets:
  postgres_user:
    file: ./postgres_user.txt
  postgres_password:
    file: ./postgres_password.txt

Untuk melakukan percobaan ini silahkan hapus dulu secret dan stack yang sudah ada dari experiment sebelumnya,
lalu jalankan all_in_one.yaml file. Lalu silahkan check secretnya dengan command "docker secret ls".
Bisa terlihat kalau 2 secret baru sudah tercipta.

Dengan cara membuat secret seperti ini, kalau kita remove stacknya, secretnya akan ikut terhapus.
docker stack rm [stack name]
docker stack rm my_project
