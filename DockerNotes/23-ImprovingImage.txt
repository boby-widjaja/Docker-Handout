Di sini kita akan mencoba menjalankan sebuah program kecil yang bisa memunculkan animasi ala film matrix di dalam terminal.
Seluruh exercise beserta contoh dan catatannya bisa ditemukan di directory Guides/CMatrix.
Tujuan dari exercise ini adalah melihat sebuah proses aplikasi sederhana diatas linux container, dimana prosesnya bisa disederhanakan
dengan proses build yang lebih lengkap. Sample dari docker file perlahan berkembang dari Sample 1 ke Sample 5, dimana sample 5 adalah yang
paling lengkap.

Seandainya saja kita ingin menjalankan proses cmatrix ini, tentu langkah yang harus kita penuhi adalah:
1. Memastikan container berisi linux distro (dalam hal ini kita pakai fedora) harus berjalan.
2. Kita harus masuk ke dalam container yang sedang berjalan, lalu bisa meng-eksekusi bash command.
3. Kenapa kita ingin meng-eksekusi bash command? Karena kita ingin install app cmatrix yang kita download dari internet
dan proses instalasinya harus lewat bash command.
4. Kita jalankan cmatrix yang sudah terinstal tadi.

Seandainya kita ingin menjalankan ini semua tanpa membuat image baru yang lebih lengkap dengan dockerfile, sebenarnya
memungkinkan saja, tetapi kita lihat apa kendalanya dan bagaimana dockerfile bisa membantu membuat image yang lebih
lengkap.

Jika kita tidak mau membuat image baru, berarti kita harus langsung run container dari image asli fedora yang kita terima dari
repository:
docker run --name cmatrix-container fedora:44

Maka code ini akan memiliki masalah, yaitu:
Container akan segera stop, karena sifat dasar container fedora:44 dari dockerhub adalah bila tidak ada proses apapun
yang berjalan di dalam container ini, otomatis di stop saja.

Oleh karena itu kita harus memastikan kalau prosesnya tidak terhenti dengan menggunakan command:
tail -f (follow the tail of the file)
tail command bisa dibaca di Shell Notes bagian HeadTail-Outputprocessing, dimana kegunaannya adalah untuk terus memonitor
sebuah file atau sebuah log yang sedang di update di bagian bagian paling belakang.
Command tail -f kita akali sebagai trick untuk membuat container tidak ditutup otomatis, 
seolah-olah "Saya masih mengawasi dan memonitor sebuah file! Jangan ditutup dulu!"
Trick untuk membuat container terus berjalan tidak harus dengan menggunakan follow tail seperti ini, tetapi
ini adalah trick umum yang biasa dipakai banyak admin ketika belajar container pertama kali.

Kalau kita ingin memonitor sebuah file, tail -f akan meminta target file yang akan di follow dalam parameter
command. Kita akan targetkan dia ke dalam directory /dev/null.
/dev/null adalah special device yang tidak pernah memiliki data dan tidak pernah bertambah isinya.
Tail akan memonitor sebuah file yang tidak akan pernah berubah.

Kalau kita menulis seperti ini, container tidak akan berhenti.
docker run --name cmatrix-container fedora:44 tail -f /dev/null
Note: Kalau kalian menjalankan command seperti ini di gitbash tidak akan berjalan lancar, karena gitbash merubah penulisan path secara otomatis.
Jadi jalankan di Linux Bash/ Windows CMD/ Powershell.

Tapi proses ini juga akan bermasalah karena walaupun container jalan, kita akan dihadapkan dengan layar kosong yang
terus menerus memantai file kosong /dev/null. Kita akan detatched proses agar container bisa berjalan di background.
Dan satu lagi mungkin kita akan terus kerepotan untuk terus menerus menghapus container yang kita buat dari hasil experiment.
Supaya container bisa terhapus otomatis, kita juga akan memberikan option remove agar saat container di stop akan terhapus otomatis:
docker run -d --rm --name cmatrix-container fedora:44 tail -f /dev/null

========== Sample 1 ===========

Tetapi harus menjalankan command ini secara terus-menerus pasti melelahkan dan tidak ada automationnya.
Dengan sample 1, kita improve agar tail otomatis selalu jalan, agar container tidak segera langsung stop.
FROM fedora:44
CMD ["tail", "-f", "/dev/null"]

Tentu saja saya gunakan CMD untuk berjaga-jaga bila siapa pun yang mau menjalankan ini tidak harus menjalankan tailnya
bila ada proses lain yang diinginkan.

Dengan ini sekarang kita bisa jalankan proses ini tanpa menggunakan tail command:
docker run --rm -d --name cmatrix-container cmatrix:1.0 

Sekarang container berjalan di background dan kita bisa masuk dengan menggunakan command execute, lalu command yang mau kita execute adalah bash:
docker exec -it cmatrix-container bash

Install cmatrix lewat bash, bila kamu menggunakan rhel, red hat, atau fedora, kamu bisa menggunakan command yang sama seperti saya,
yaitu dengan menggunakan dnf, kalau kalian pakai keluarga debian, ubuntu atau alpine, bisa menggunakan command apt.
sudo dnf install -y cmatrix
(Kalau switch user ke root, sudo tidak diperlukan, bisa baca Shell Notes bagian permission)

Silahkan experiment program cmatrix dan lihat apa saja optionnya dari:
cmatrix --help

========== Sample 2 ===========

Walaupun semua sudah berjalan sesuai dengan yang diinginkan, tetapi semua proses ini masih bisa dipersingkat dengan 
membuat kita tidak perlu repot harus install cmatrix terlebih dahulu setiap kali container hidup.
Di sini kita akan improve dengan sample 2, yaitu kita akan install cmatrix pada saat proses build, sehingga ketika
di run ke dalam container, kita tidak perlu lagi menginstall cmatrix app.
FROM fedora:44
USER root
RUN dnf install -y cmatrix \
    && dnf clean all
CMD ["tail", "-f", "/dev/null"]

Di sini kita bisa jalankan command seperti yang ada di sample sebelumnya, hanya saja tidak perlu install
sudo dnf install -y cmatrix.

========== Sample 3 ===========

Tapi pada sample 2, kita masih perlu untuk masuk ke dalam container dan execute bash, dan ketika di dalam bash terminal
kita masih perlu execute cmatrix-nya. Mungkin bisa kita persingkat, agar ketika container di jalankan, cmatrix bisa langsung jalan.
Yang menjadi masalah di sini adalah command yang harus di execute ada 2, yaitu bash dan cmatrix, dimana cmatrix sendiri
adalah bash command yang harus dijalankan di dalam terminal bash.

Pada sample 3, kita bisa mengubah CMD instruction menjadi:
CMD ["bash", "-c", "cmatrix -s -C blue"]

atau kalau dituliskan langsung di dalam terminal bisa terlihat seperti:
bash -c cmatrix -s -C blue

dimana arti dari -c pada bash sendiri artinya kalau sisa text dibelakang saya adalah parameter string,
dimana string itu adalah command yang nantinya akan diexecute ketika bash terminal sudah aktif.
Jadi bisa dibayangkan dengan seperti ini:
bash -c "cmatrix -s -C blue"

Tetapi sekarang kita wajib run container dengan menggunakan option -it.
Karena cmatrix adalah program yang jalan di dalam interactive terminal, jadi kalau tidak ada option -it, 
cmatrix tidak akan berjalan. Jadi bisa kita simpulkan kita pindahkan -it dari exec ke run.
docker run --rm -it --name cmatrix-container cmatrix:3.0

========== Sample 4 ===========

Tidak banyak perubahan dari sample 3 ke sample 4. Yang dilakukan pada sample 4 adalah memisahkan shell command ke dalam:
ENTRYPOINT untuk bash
CMD untuk cmatrix

Kenapa dibuat seperti ini? Karena saya yakin bash selalu ingin saya jalankan, tetapi saya tidak
selalu yakin kalau cmatrix yang saya ingin jalankan adalah cmatrix berwarna biru atau bersifat screen saver.
bisa jadi cmatrix yang saya mau jalankan adalah: cmatrix -bs -C red

dengan ini saya memberikan 2 choice untuk menjalankannya secara default:
docker run --rm -it --name cmatrix-container cmatrix:4.0
atau di override:
docker run --rm -it --name cmatrix-container cmatrix:4.0 "cmatrix -bs -C red"

========== Sample 5 ===========

Kita ingin menambah sedikit variasi pada Sample 5. Kita ingin multiple command statement yang berjalan secara
sequential dan synchronous. Maksud saya adalah saya ingin agar ada 3 statement cmatrix, cmatrix berwarna biru, merah dan hijau,
dimana pertama-tama akan jalan yang biru terlebih dahulu, setelah yang biru di stop dan sudah selesai barulah yang merah berjalan.
Dimana ketika merah masih berjalan yang hijau akan menunggu merah utuk selesai:

cmatrix -s -C blue;
cmatrix -s -C red;
cmatrix -s -C green

Jadi operator ; berarti: "Jalankan command berikutnya setelah command sebelumnya selesai, tanpa peduli apakah berhasil atau gagal."

Jadi proses itu bisa kita tulis di docker instruction seperti ini:
CMD ["cmatrix -s -C blue; cmatrix -s -C red; cmatrix -s -C green"]

Silahkan jalankan sample 5 seperti menjalankan sample 4 sebelumnya.
