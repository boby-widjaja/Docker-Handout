Process adalah sebuah program yang sedang dieksekusi oleh OS saat ini.
Sama seperti running task pada Task Manager di dalam windows.
Saat ini seluruh processes yang sedang berjalan akan memakan performance pada temporary memory atau RAM.

Command-command yang digunakan untuk memperlihatkan process:

List process yang berjalan hanya di terminal shell saat ini, tidak yang di shell lain atau di background:
ps

Menunjukan seluruh process yang sedang jalan di OS:
ps -e

Menunjukan seluruh process hanya untuk selected user:
ps -u [username]
ps -u bobywidjaja

Menunjukan process dalam full format:
ps -f 
ps -ef
ps -f -u bobywidjaja

Menunjukan seluruh process pada OS dengan BSD (Berkeley Software Distribution) format:
ps aux

Command ps dimana kita bisa custom dan organized sendiri ingin melihat column apa saja:
ps -o [FORMAT]
ps -o pid,psr,cmd

Karena variasi column yang bisa dilihat dari satu process, saya akan bahas hal-hal yang sering dipakai, 
atau yang keluar di ps, ps -f dan ps aux terlebih dahulu:
-) PID: process id
-) PPID: Parent Process ID — yaitu PID dari proses yang menjadi induknya.
-) UID / USER: owner dari proses ini, id dan usernamenya.
-) GID / GROUP: group dari proses ini, id dan nama groupnya.
-) TTY: TeleTYpe, dan secara praktis menunjukkan id terminal yang terhubung pada process tersebut.
    untuk mengetahui identitas terminal yang saat ini kamu sedang operasikan, pakai command:
    tty 
    untuk melihat seluruhnya bisa gunakan command:
    who
-) TIME: total durasi waktu yang di-spend oleh CPU untuk process ini. bukan berapa lama process sudah berjalan.
-) STIME / START: (Start Time) jam berapa process ini mulai
-) CMD / COMMAND: Command program yang digunakan untuk menjalankan process ini.
-) C: Nilai penggunaan CPU berdasarkan system unix jaman dahulu, sudah sangat jarang digunakan karena
    dinilai lebih sulit dimengerti dan masih ada cara alternative pengukurannya. 
    Nilai CPU Utilization di dapat dari = TIME / ELAPSED TIME.
-) %CPU : Persentase penggunaan CPU oleh process.
-) PSR: Nomor logical CPU (processor/core) tempat thread/process tersebut terakhir kali dieksekusi.
-) VSZ: Virtual Memory Size, dalam satuan KiB. Jumlah memory yang di book untuk proses ini dari RAM.
    Note: KiB adalah Kibi byte bukan KB Kilo Byte.
    1 KiB = 1024 bytes
    1 KB = 1000 bytes
-) RSS: Resident Set Size, juga biasanya dalam KiB. Jumlah memory yang terpakai di dalam Virtual Memory Size oleh proses ini.
-) %MEM : Berapa % RAM yang digunakan
-) STAT: Status Process
    Status process memiliki 2 bagian pada valunye:
        Karakter pertama = state utama process
        Karakter setelahnya = atribut/flag tambahan

    Huruf pertama menunjukkan state utama:
    | STAT | Nama                  | Arti sederhana                                            |
    | ---- | --------------------- | --------------------------------------------------------- |
    | `R`  | Running / Runnable    | Sedang berjalan atau siap dijalankan CPU                  |
    | `S`  | Interruptible sleep   | Sedang menunggu sesuatu, dan bisa dibangunkan oleh signal |
    | `D`  | Uninterruptible sleep | Sedang menunggu operasi kernel tertentu, biasanya I/O     |
    | `T`  | Stopped               | Process dihentikan                                        |
    | `t`  | Tracing stop          | Berhenti karena sedang di-trace/debug                     |
    | `Z`  | Zombie                | Process sudah selesai, tetapi entry-nya masih ada         |
    | `I`  | Idle                  | Kernel thread idle                                        |

    Atribut/flag tambahan
    | Karakter | Arti                                         |
    | -------- | -------------------------------------------- |
    | `s`      | Session leader                               |
    | `+`      | Foreground process group                     |
    | `l`      | Multi-threaded                               |
    | `<`      | High-priority / elevated scheduling priority |
    | `N`      | Low-priority / low scheduling priority       |
    | `L`      | Pages locked into memory                     |
    | `        | `                                            |

Kita juga bisa menggunakan perintah top selain ps untuk memonitor semuanya itu secara terus-menerus:
top

Menentukan refresh rate dalam detik:
top -d [seconds]
top -d 2
Refresh setiap 2 detik.
Default biasanya sekitar 3 detik.

Memonitor selected PID:
top -p [PID]
top -p 1234
Beberapa PID:
top -p 1234,5678,9012

Memonitor selected user:
top -u [username/UID]
top -u bobywidj

Mengubah tampilan top monitoring dengan beberapa hot key:
c: untuk view command dalam absolute path
k: kill process yang ditunjuk
M: sort berdasarkan memory
P: sort berdasarkan cpu
N: sort berdasarkan PID
1: Tampilkan setiap logical core daslam CPU
f: untuk custom column field sesuai dengan yang kita mau lihat


=============================== SIGNAL ====================================

Kita bisa memberi perintah ke OS kernel, agar OS kernel mengirim signal ke salah satu process, lalu
signal handler akan melakukan suatu action ke process tersebut. Action pada process itu bisa
berupa penghentian process, melanjutkan process, reload process, dan masih banyak lainnya.

Signal bisa dikirim oleh macam-macam hal, misalnya:
-) dikirim oleh kill command
-) dikirim oleh sleep command
-) dikirim oleh systemctl command
-) dikirim oleh keyboard terminal, misalnya Ctrl + C atau Ctrl + Z
-) k key pada top monitoring (sudah dibahas sebelumnya)
-) Docker instruction STOPSIGNAL
-) otomatis dari kernel karena kondisi dan operasi tertentu

Ada bermacam-macam signal, dan setiap signal punya nomor unik masing-masing.
Di bawah ini saya tampilkan signal yang relatif lebih sering dipakai, 
tentu saja tidak semua saya tampilkan dan jelaskan.

| Signal      | Nomor     | Kegunaan                                                  
| ----------- | --------: | ---------------------------------------------------------
| SIGTERM     |        15 | Meminta process berhenti secara graceful, save data, clean sebelum closing.
| SIGKILL     |         9 | Memaksa process berhenti (force kill).
| SIGINT      |         2 | Interrupt dari keyboard, biasanya `Ctrl+C`.
| SIGTSTP     |        20 | Stop dari terminal, biasanya dari `Ctrl+Z` atau sleep command.
| SIGSTOP     |        19 | Memaksa process berhenti sementara (Paused), bentuk force dari SIGTSTP
| SIGCONT     |        18 | Melanjutkan process yang stopped (Resume)
| SIGHUP      |         1 | Hangup; sering digunakan untuk reload/restart konfigurasi
| SIGCHLD     |        17 | Signal yang dikirim dari child ke parentnya karena perubaha statusnya. (keseringan otomatis, bukan manual)
| SIGSEGV     |        11 | Sering kita temui karena bug dan crash suatu program karena Access Invalid Memory.
| SIGQUIT     |         3 | Mirip seperti SIGSEGV tapi dilakukan dengan sengaja dengan Ctrl+\


Untuk melihat list signal yang ada, kita bisa menggunakan command:
kill -l

Kita bisa mengirim signal dengan command kill dengan structure seperti berikut:
kill -[signal name/ signal number] [PID]
kill -15 5678
kill -SIGTERM 5678

Kalau kita tidak menulis signal name atau signal number, misalnya:
kill 5678, SIGTERM adalah defaultnya.

Untuk menghentikan process, saya sarankan menggunakan SIGTERM selalu, tetapi
kalau terjadi sesuatu pada process dan tidak bisa berhenti, saya sarankan gunakan alternatif SIGKILL.

Baik SIGSEGV dan SIGQUIT meninggalkan Core Dump.
Core dump adalah snapshot isi/memori dan state process ketika process mengalami crash/termination tertentu.
Jadi sifatnya seperti error log. Tujuannya supaya developer bisa melakukan debugging.

Kita juga bisa kill dengan menggunakan nama process atau nama command, dimana biasanya
command yang sama memiliki lebih dari satu process, misalnya:
PID    COMMAND
1234   firefox
2345   firefox
3456   firefox

Untuk melakukan kill lebih dari satu sekaligus berdasarkan nama 'firefox" nya:
killall -[signal name/ signal number] [Command]
killall -SIGTERM firefox
